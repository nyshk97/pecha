# Pecha — 自分専用の音声入力アプリ

## 概要・やりたいこと

いま使っている音声入力アプリ KeyVoice（v1.6.0）を、自分が使う機能だけの自作アプリ **Pecha** に置き換える。

KeyVoice への不満:
- Brewfile で入れられない
- 新しい Mac ではアクティベーションコードを過去のメールから探して入れる必要がある
- ショートカットを押しても反応しないことがある（起動・常駐が不安定）
- 設定・モデル選択が多いが、自分は 1 つの構成で固定して使う
- 辞書登録までの手順が遠い

ねらい: 「押している間だけ録音 → 離したら貼り付け」が確実に動き、誤認識はその場で選択して直すだけで辞書に登録できること。Brewfile 1 行で全部の Mac に入り、辞書も Dropbox で共有する。

## 前提・わかっていること

### KeyVoice の調査結果（2026-10-02）
- 文字起こしは **Apple の `SpeechAnalyzer` + `SpeechTranscriber`**（macOS 26 の OS 標準）。import しているのは `SpeechTranscriber(locale:preset:)`・`.transcription` / `.progressiveTranscription` preset・`AssetInventory.assetInstallationRequest(supporting:)`・`SpeechAnalyzer.start(inputSequence:)`・`finalizeAndFinishThroughEndOfInput()`・`bestAvailableAudioFormat(compatibleWith:)`
  - 設定は `selectedASREngine = ""`（既定）で、Qwen3-ASR・Cohere 等の別モデルはダウンロードされていない → **精度は OS の音声認識のもの**。Pecha で同じ API を使えば同じ精度になる見込み
  - `AnalysisContext`（`contextualStrings`）は使っていない。辞書は認識後の置き換え（`dictionary_replacement_hit` というイベント名）とみられる。`SFSpeechLanguageModel` も import しているが用途は未確認
- 実際に使っている設定: 左 ⌘ + Space を押している間だけ録音、言語 `ja`、開始音 `Funk`、終了音 `Bottle`、LLM による整形はオフ、メニューバーアイコンは非表示
- 9/29 のクラッシュは LLM 整形用の部品（llama.cpp の `ggml_uncaught_exception`）の中で起きていた。整形はオフなのに、この部品が動いていた。使っていない部品を積んでいることが不安定さの一因とみる
- KeyVoice の辞書データは設定ファイル・コンテナ内に見当たらなかった → **移行はしない**（登録済みの語があればユーザーが一覧を渡し、初期の辞書に入れる）
- KeyVoice のコード・素材は流用しない。Apple の公開 API だけで作る

### 決定した仕様（/dig-lite）
| 項目 | 決定 |
|---|---|
| 録音 | 左 ⌘ + Space を**押している間だけ**録音。離したら文字起こしして前面のアプリに貼り付け |
| 作らないもの | F5 での開始・停止、直前の結果の貼り直し、履歴、録音中の途中経過の表示、設定画面、LLM 整形、モデル選択 |
| 録音中の表示 | 画面の隅に録音中のマークと音量だけを出す（HUD） |
| 辞書登録 | 貼られた文の誤認識部分を選択して **右 ⌥ + 2** → パネルで正しい語を入れて Enter → 辞書に「誤 → 正」を保存し、選択部分もその場で正しい語に置き換える |
| 辞書の効かせ方 | 認識後に「誤 → 正」で置き換える（認識時のヒント `contextualStrings` は Phase 0 で効果が無かったので使わない） |
| 辞書の置き場 | Dropbox 上のテキストファイル（全部の Mac で共有。手でも編集できる） |
| 固定値 | 言語 ja_JP、ホットキー（常用版: 左 ⌘ + Space / 右 ⌥ + 2。dev 版: 右 ⌘ + Space / 右 ⌥ + 3）、効果音（Funk / Bottle）。設定画面は作らない |
| 名前 | 常用版 **Pecha** / 開発版 **Pecha Dev**。Homebrew 公式に同名の cask・formula は無い（確認済み） |

### 設計上の決め事（会話の後に自分で決めたもの。違和感があれば変える）
- **作りは capit（`~/capit`）を見本にする**: XcodeGen・`signing-*.local.xcconfig` の生成と ad-hoc へのフォールバック・`CLAUDECODE` のときは証明書で署名しない mise タスク・`scripts/{release,preflight,notarize,make-release-zip,changelog,install-app}` を写して名前を変える。リポジトリは `nyshk97/pecha`（capit と同じく public、Release も同じリポジトリ。Sparkle feed は `https://github.com/nyshk97/pecha/releases/latest/download/appcast.xml`）
- bundle id: 常用 `io.github.nyshk97.pecha` / dev `io.github.nyshk97.pecha.dev`（capit と同じ命名）
- `LSUIElement`（Dock に出さない）。**メニューバーアイコンは小さく置く**: バージョン表示・アップデートを確認・辞書ファイルを開く・終了だけ（Sparkle の入口と、異常に気づく場所が要るため）。録音中・エラーはアイコンの見た目にも出す
- 常駐アプリなので Sparkle の自動チェックは ON（personal-mac-apps.md の基準）
- **dev 版は常用版・KeyVoice と並行して動かせるよう別のキーにする**（capit と同じ考え方。決定表の固定値を見よ）
- ログイン時の起動は `SMAppService.mainApp`（初回起動時に登録。設定画面は作らない）。**登録は常用版だけ**（dev 版はログイン時に起動しない）
- 辞書ファイル: `~/Library/CloudStorage/Dropbox/settings/pecha/dictionary.txt`。1 行 1 件、`誤 => 正`、`#` 始まりはコメント（`=>` が無い行は無視する）。**録音のたびに読み直す**（別の Mac で足した語がすぐ効く。監視の仕組みは持たない）。読み込みは押下と同時に非同期で始め、失敗したら前回読めた内容を使う（`dict.load_failed`）。ファイルが無ければ最初の書き込みで作る。Dropbox の下のファイルに初めて触ると TCC の確認が出て答えるまで止まるので、**ファイルにはメインスレッドで触らない**（起動時の読み込みで確認が出る＝初回に許可を求める流れ。拒否されたらメニューに出す）。**書き込みは常に末尾への追記だけ**（ファイル全体を書き直さない。手で編集している最中の内容を書き潰さないため）。追記の前に最後の 1 バイトを見て、改行でなければ改行を補う。同じ「誤」が複数あれば**後の行を採用する**（last-wins）
- ログ: `~/Library/Logs/pecha/pecha.log` / `pecha-dev.log`。イベント名は固定（`hotkey.down` `record.start` `record.stop` `asr.done` `asr.empty` `paste.done` `dict.add` `tap.reenabled` 等）。**文字起こしの本文はログに書かない**（文字数だけ）。dev フック `--transcribe-file` の結果の本文はログでなく stdout に出す
- 「押しても反応しない」への対策（KeyVoice の不満の本丸）:
  - グローバルホットキーは `CGEventTap` で取り、⌘ + Space と右 ⌥ + 2 を前面アプリに届かないように飲み込む。タップは `.tailAppendEventTap` で作る（keyrc のタップが先に Space を見られるように。keyrc は左 ⌘ の単独タップで「英数」を送り、途中の keyDown で取り消す作りなので、Pecha が先に Space を飲むと入力ソースが英字に変わる）
  - 左右の ⌘・⌥ は修飾フラグの機種依存ビットで見分ける。録音を始めたら、Space の keyUp までは Space の keyDown（リピートを含む）と keyUp を全部飲み込む（⌘ を先に離しても Space のリピートが前面アプリに漏れない）
  - タップのコールバックは判定だけにして、音・録音の開始などの処理は非同期で投げる（コールバックが遅いと `DisabledByTimeout` の原因になる）
  - `kCGEventTapDisabledByTimeout` / `ByUserInput` を受けたら即座に再有効化し、加えてタイマーで `CGEvent.tapIsEnabled` を監視する（タップが黙って止まるのが「反応しない」の典型的な原因）
  - キーを押した瞬間に開始音を鳴らす（音が鳴らなければ「キーが届いていない」と切り分けられる）。認識の準備ができていなければ HUD にエラーを出す
  - アクセシビリティの許可が無いときは、メニューバーアイコンとログで分かるようにする。許可が無い間は監視タイマーで待ち、許可が出たらタップを作る
  - 合成した ⌘V / ⌘C には `eventSourceUserData` に印を付け、自分のタップの状態遷移に入れない（貼り付けの ⌘ の解放を「⌘ を先に離した」と取り違えない）
  - セキュア入力（パスワード欄など）が ON の間はキーが届かないので、監視タイマーで見てログ（`secure_input.on/off`）とアイコンに出す
  - タップの停止・スリープ復帰を検知したら、物理キーの状態と照合して keyUp の取りこぼしで録音が続かないようにする
- 貼り付け: クリップボードに入れて合成 ⌘V（修飾は `flagsChanged` で送る。swift-projects.md の合成キーの節）→ 元のクリップボードを戻す（Electron の遅延書き戻し対策で約 1 秒監視）。元のクリップボードは全部の item の全部の type を取っておく（文字列だけだと画像・ファイルが壊れる）。一時的に置く本文には `org.nspasteboard.TransientType` を付ける（クリップボード管理アプリに本文を残さない）。結果が空なら貼らない（`asr.empty`）
- 貼り付け先に入力欄が無いときの判定はしない（常に貼ってクリップボードを戻す。話した内容はその場合消える）（1回目で決定）
- マイクは押下ごとに動かし、常時は動かさない（メニューバーにオレンジのマイク表示が出続けるため）。Phase 0 / Phase 2 で録音の頭切れが目立てば見直す（1回目で決定）。`AVAudioEngine` も押下ごとに作り直す（入力デバイスの切り替え・スリープ復帰でエンジンが黙って止まるのを避ける）。マイクの許可は最初の押下でなく起動時に求める
- 選択テキストの取得（辞書登録）: `AXSelectedText` → Copy メニューの AXPress → 合成 ⌘C の順に試す（swift-projects.md の段階フォールバック）。後の 2 つでクリップボードを使ったときも、貼り付けと同じ戻し方で元に戻す（取る → 戻す → パネル → 置き換える → 戻す）
- 短すぎる押下（約 0.3 秒未満）は録音を捨てる。⌘ を先に離した場合も録音を止める
- システム設定の Spotlight の ⌘ + Space は、この Mac では外れている（`com.apple.symbolichotkeys` の 64 が `enabled = 0`。2026-10-02 確認）。ほかの Mac は動作確認のときに見る

### この Mac（会社貸与 PC `TsubasanoMacBook-Pro`）での制約
- Claude Code のセッションからは keychain に触らない（`security find-identity`・`codesign --sign`・`notarytool`・`sign_update`・`generate_keys`・`mise run release`）。capit と同じく、セッションからのビルドは ad-hoc 署名にする
- そのため **セッションのビルドでは TCC（マイク・アクセシビリティ）の許可がビルドのたびに外れる**。自動の確認は TCC の要らない経路（音声ファイルを読ませる dev フック・単体テスト）で組み、マイク・ホットキー・貼り付けの実機確認はユーザーが署名済みのビルドで行う
- 環境: macOS 26.6.2 / Xcode 27.0 / xcodegen・mise あり
